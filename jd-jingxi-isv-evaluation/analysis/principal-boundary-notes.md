# 产品边界审核记录

以下为基于需求与已有能力事实的初步技术推断，接口结论待候选证据审核后写入正式矩阵。

## 必须保留的产品差异

1. 商品经营“潜力SKU识别”和流量增长“潜力SKU”保留独立ID。前者关注投入资源的综合价值，后者关注流量放大机会；可共享数据和评分基础，但不能未经确认合并验收范围。依据：需求清单第16、53行。
2. AI素材“广告创意生成”明确基于广告效果；广告经营“创意生成”只明确图片及卖点。前者不能用单纯生成能力替代效果输入，后者可先定义为用户提供商品资料的单次生成。依据：第29、79行。
3. 动态调价原文要求持续给出策略，不直接证明自动改价需求。自动改价属于获得授权后的自动执行模块，必须另行定义触发条件、价格底线和审批边界。依据：第41、102行。
4. 一键提报存在“直接报名”或“生成提报底表”两条路径。底表路径不依赖报名写接口，但仍依赖活动模板和规则。不得将底表交付描述为线上报名成功。依据：第64行。
5. 毛利测算与ROI底线可先基于商家明确输入成本、费用和补贴规则计算；真实结算口径和自动数据接入是另一层能力，不能用推测费用形成实际利润承诺。依据：第39、40行。
6. 主图视频不是已有静态生图能力的直接复用事实。依据：第26行、已有能力第41–49行。
7. 策略实验与策略学习需要稳定的动作ID、结果窗口、归因口径和对照控制；普通前后对比不能证明因果增量，也不能承诺学习必然改善经营结果。依据：第105–106行；技术推断。

## 经营自动化评估框架

目标链路：授权数据输入 → 规则/诊断 → 候选任务与冲突排序 → 商家确认或授权策略 → 受控动作 → 结果核验 → 指标观察 → 实验复盘。

须分开判断动作接受、动作生效、经营指标改善三个状态。重复任务防重、执行前状态校验、动作额度约束、失败重试边界、人工暂停及操作追溯属于拟新增工程要求，不作为已具备事实。数据事件可采用回调或满足业务时效的轮询；只有明确要求的时效无法由轮询满足时，才能把Callback作为硬性接口缺口。依据：需求第101–107行；已有能力第27–33、107行；技术推断。

## 预期协同问题的去重原则

按数据/接口合同合并，而不是每个模块重复问“有没有接口”。每个合同须确认业务适用范围、实体标识、字段口径、时间粒度、历史范围、刷新时延、权限、配额；写操作增加状态机、部分成功、幂等及回执规则。只对实际需求涉及的合同提出，不预设京东内部实现。
