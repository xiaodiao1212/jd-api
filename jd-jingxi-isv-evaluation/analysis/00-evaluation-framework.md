## 维度定义

|维度|评估口径|
|---|---|
|Existing Capability|高：核心产物已明确具备；中：核心工作有部分基础；低：仅相关经验；无：文档没有该专用能力事实。常规 SaaS 承载单列，不将其泛化为业务能力|
|复用分类|DIRECT_REUSE：原文明确同类核心能力；PARTIAL_REUSE：已有能力覆盖部分行为；KNOWHOW_REUSE：仅方向经验；NO_EXISTING_CAPABILITY：基线没有该专项能力事实，不代表历史上绝对不存在；UNKNOWN：具体实现无法确定|
|SaaS Productization|代表产品化新增复杂度，低：单次输入输出；中：批量、状态、规则配置或多源连接；高：持续自动执行、实验归因或跨域协作|
|JD Data Dependency|低：用户供给资料即可形成核心产物；中：平台数据增强或必要上下文；高：主要经营判断依赖平台数据；核心依赖：缺数据即无法兑现该核心产品承诺|
|Public API Coverage|FULL：本需求需要的平台交互完整且字段有证据；PARTIAL：仅部分数据或动作；NONE_FOUND：必要接口在本次资料中未发现，使用OPEN_API_NOT_FOUND；NOT_REQUIRED：核心边界不需要京东接口，可由用户输入资料。不是对整项产品完成度评分|
|Permission Status|涉及平台调用默认UNKNOWN；仅有明确应用授权证据才CONFIRMED；无平台调用需求才NOT_REQUIRED|
|Research Complexity|R0成熟工程；R1规则/LLM；R2分析/评分/排序；R3预测/优化；R4持续实验/反馈学习。按满足原文承诺所需主要能力，不以使用AI即提高等级|
|Automation Level|T0单次；T1批处理；T2定时；T3持续监控；T4自动决策执行；T5动作结果策略闭环。表示目标形态，不表示已有完成；原文不明确的自动写回不能擅自纳入承诺|

## 综合产品判断

A：核心能力可直接产品化；B：基于既有能力二开；C：专项研发；D：平台数据/接口构成主要依赖；E：需要双方联合定义或研发协同。每项标注一个主要标签和必要辅助标签。普通权限确认不自动升级为E；接口语义、数据定义或实验控制能力未明且决定产品边界时才采用E。

每项明确一个首要困难：现有能力缺口、SaaS工程、京东接口、京东数据、算法、业务规则、自动化基础设施、授权/风控；其他限制在解释或协同事项中保留。

## 需求解释约束

生成建议不自动等于回写；动态调价原文仅要求持续给出策略；一键提报允许生成底表作为独立合规交付路径；素材批量处理原文包含替换，不能仅以生成能力判断完成；AI客服回复包含配置模板，不能仅以生成话术判断完成；实验效果比较不等于因果增量证明。
