# 京东京喜 ISV 产品需求评估说明

以《京东京喜-ISV-需求清单》为基础，逐项说明已有基础、需要补齐的能力，以及与京东协作的重点。

## 总体判断

我方现有产品中，能直接借用的是商品素材生成和商品信息优化。Sico AI 生图侠已有商品图片、一键主图、一键详情页及批量素材处理功能；Sico AI 巡检侠已有商品信息诊断、优化及围绕信息分的优化基础。本项目可沿用这些能力，再适配京喜的商品规范和发布要求。

经营分析与操作产品仍有不少工作要做。比如，判断潜力商品要有经营数据和评价方法，推荐活动要知道资格与利润约束，调整广告则涉及效果数据、预算限制和调用权限。这些都需逐项开发或对接。

经营自动化还要解决任务如何排序、哪些操作可自动执行，以及做完后怎样检查效果。我方已有线上软件服务基础，可以承载入口和页面；复杂任务管理、持续监控及策略学习是否已有可用实现，目前尚未确认。

### 各模块概览

| 模块 | 可以从哪里开始 | 最需要解决什么 |
|---|---|---|
| 商品经营 | 复用商品信息诊断与优化基础 | 完整发品、内容写入及经营数据。 |
| AI素材 | 复用主图、详情页和批量素材能力 | 京喜适配、线上替换、视频及效果测试。 |
| 比价与定价 | 开发成本测算和价格建议功能 | 可信的竞品价格、商家成本和费用规则。 |
| 流量增长 | 从标题、素材优化扩展到分析 | 分商品、分渠道的曝光与成交数据。 |
| 活动经营 | 结合招标方流程梳理各类活动 | 官方资格、冲突规则和报名方式。 |
| 广告经营 | 以已有公开操作资料开展对接确认 | 效果数据、投放策略及授权执行。 |

| 经营自动化 | 在现有软件基础上建设任务系统 | 排序、授权、执行结果及持续效果检查。 |

### 表格口径

“招标方已有流程”沿用原清单的“是否已有”。“是”指招标方已有对应工具流程，不能据此认定我方已实现或已能向商家交付；“否”保留原标记。经营自动化部分未给出标记，统一写为“未说明”。

文中区分已有产品能力和平台对接条件。公开接口资料存在，并不意味着已经适用于京喜或我方已有调用权限；当前未找到的接口，也需向京东核实是否有可开放的内部能力。

SKU指商品的具体可售规格；CTR是点击率，CVR是转化率，ROI是投入产出比，GMV是成交金额。经营计算还需统一各指标的统计范围。A/B测试指比较两套方案的效果。

标题、卖点、属性和信息分优化，可以借用巡检侠的相关能力。商品创建还要完成平台写入与发布；商机推荐和潜力商品识别，则需要店铺及行业数据支持。

| 产品需求与原始目标 | 招标方已有流程 | 产品评估 |
|---|---|---|
| **商机推荐**<br>根据商家类目及行业热销趋势识别可经营商品机会 | 否 | 商机筛选和推荐要新开发。已有公开资料包含类目热度、供需等数据，能否用于具体商家，还取决于覆盖类目、更新频率和商家的可经营条件。 |
| **一键发品**<br>自动生成标题、属性、卖点、图片、详情并创建商品 | 否 | 图片和商品信息生成可以复用。接下来要把内容组合、类目校验和商品创建连起来，确认各项内容能否完整写入，以及怎样检查发布结果。 |
| **AI标题优化**<br>识别标题问题并生成推荐标题 | 是 | 可沿用巡检侠的商品信息优化经验，按京喜标题规范适配。适配后，可根据商家提供的准确资料生成推荐标题；直接替换线上标题的范围另行确认。 |
| **短标题/卖点**<br>自动生成短标题及核心卖点 | 是 | 商品信息生成与优化能力可以复用。主要工作是按字数和表达要求提炼商品特点，避免写出商品本身不具备的卖点。 |
| **商品属性补全**<br>自动识别并补齐缺失属性 | 否 | 巡检侠已有信息问题识别和优化基础。补哪些属性、填什么值，要结合类目要求和商品资料判断；无法核实的值交商家补充，线上写入范围仍待确认。 |
| **信息分优化**<br>根据扣分项自动完成标题、图片、属性、详情优化 | 是 | 与巡检侠的现有业务较接近。适配时要逐一对齐扣分规则和可修改内容，并检查修改后的生效状态、重新计分时间及分数变化。 |
| **商品搬运**<br>支持多平台商品链接导入并完成商品创建 | 是 | 已有能力能处理部分商品内容，跨平台链接解析和字段转换还要开发。来源资料是否可取得、素材能否使用，以及京东端如何完整创建商品，都需落实。 |
| **潜力SKU识别**<br>识别值得重点投入经营资源的SKU | 否 | 要新建商品评价方法。判断是否值得投入，需要本店销售、利润和库存等资料，行业热销信息只能提供参考。 |
| **一品一策**<br>为重点SKU生成完整经营方案 | 否 | 商品信息经验可以借用，但完整经营方案仍需开发。方案要综合价格、流量、活动和广告资料；原需求到生成方案为止，未要求自动执行。 |

商品模块需与京东确认完整的创建、编辑流程和信息分规则。商机及店内经营数据能提供到什么范围，也会影响推荐功能的设计。

主图、详情页和批量素材是我方已有产品的主要能力，套图与广告素材可在此基础上适配。视频生产、线上替换和素材效果测试的工作需分别评估。

| 产品需求与原始目标 | 招标方已有流程 | 产品评估 |
|---|---|---|
| **AI主图生成**<br>根据商品信息生成主图 | 是 | 已有一键主图和商品生图能力，可用于本项目。适配工作主要围绕京喜主图规范和商品还原；线上上传或替换需另行确认。 |
| **商品套图**<br>生成白底图、场景图、规格图、卖点图 | 是 | 可在商品生图能力上开发。白底、场景、规格和卖点图各有用途，应分别设计与验收，规格信息尤其需要商家资料支持。 |
| **商详图生成**<br>自动生成详情图及详情结构 | 否 | 我方已有一键详情页能力，可以复用。招标方此项标记为“否”不影响这一判断；本项目要适配的是京喜详情结构、内容规范和具体商品资料。 |
| **主图视频**<br>自动生成商品视频 | 否 | 视频生产需要新增能力。现有资料确认的是图片和详情页功能，商品视频生成、连续画面检查及审核流程尚未确认具备。 |
| **批量素材处理**<br>支持多SKU批量生成及替换 | 是 | 批量生成与处理可以复用，线上替换还要开发对接流程。每份素材必须对应到正确商品和位置，部分失败或重复操作也要能检查、处理。 |
| **主图A/B测试**<br>支持素材测试、效果跟踪及优胜方案选择 | 否 | 资料中已有素材实验和分流功能，可用于对接。选出更好的方案，还需要各版本效果数据、有效样本要求和优胜素材应用规则，实验评价功能要另行建设。 |
| **广告创意生成**<br>基于广告效果生成新创意 | 否 | 素材生成能力可以复用，但本项要根据投放效果改创意。必须先知道每套创意对应的结果，才能据此调整图片和表达。 |

素材对接主要涉及规格、批量替换和实验结果。对于效果驱动的功能，还要能把数据对应到具体创意，并确认优胜素材怎样正式应用。

## 三、比价与定价能力

我方现有能力资料没有确认专门的比价、定价产品。这一模块首先要落实竞品价格、历史记录和商家成本，并约定利润怎样计算。平台建议价和价格竞争力信息可作参考。

| 产品需求与原始目标 | 招标方已有流程 | 产品评估 |
|---|---|---|
| **同款识别**<br>识别站内外同款/相似商品 | 是 | 商品匹配功能需要开发，前提是取得可使用的站内外商品资料。完全同款与相似品要分开判断；当前资料未发现完整对应的公开接口，数据来源仍待确认。 |
| **实时比价**<br>获取竞品实时价格及促销价格 | 是 | 先解决竞品价格从哪里来、多久更新。地区、人群和促销条件会影响到手价，比较条件确定后，才能约定“实时”具体到什么程度。 |
| **价格趋势**<br>展示竞品历史价格变化 | 是 | 展示趋势需要历史价格记录。过去的数据能否取得、今后的数据能否持续积累，是两项不同条件，当前尚不能承诺完整的历史回溯。 |
| **建议价格**<br>结合竞品、毛利、平台规则给出建议价 | 是 | 定价判断需要开发。平台建议价可以参考，还要结合商家成本底线、竞品情况和活动规则。此项交付建议价，不默认自动修改售价。 |
| **毛利测算**<br>计算活动、广告、补贴等情况下的实际利润 | 是 | 可以开发成本与利润计算工具。要算实际利润，采购、履约、广告、补贴和退款费用都得对应清楚；商家输入的测算结果应与结算利润分开呈现。 |
| **ROI指导**<br>根据成本结构给出广告ROI底线 | 否 | 可先开发由商家填写成本的计算工具。广告收入、费用和利润采用同一口径后，才能算出投放底线；缺失成本应补充，不能估填。 |
| **动态调价**<br>根据竞争环境变化持续给出调价策略 | 否 | 持续给建议，需要持续取得竞争变化，并结合成本底线判断。若商家还希望系统直接改价，应另外约定授权、价格限制和可调用的操作。 |

站内同款、竞品价格和费用规则需向京东核实。站外数据与商家自身成本由谁提供，应一并约定。

## 四、流量增长能力

标题和素材优化有复用基础，流量分析要新开发。分析时需区分搜索、推荐与广告渠道；广告数据只覆盖其中一部分。

| 产品需求与原始目标 | 招标方已有流程 | 产品评估 |
|---|---|---|
| **CTR诊断**<br>识别曝光高但点击低的商品 | 否 | 分析要用到商品曝光、点击及渠道数据，再按样本和观察时间判断点击率是否偏低。现有报表框架与部分广告数据能否覆盖所需范围，仍待确认。 |
| **CVR诊断**<br>识别点击充足但转化不足的商品 | 否 | 点击和成交要对应到同一商品、渠道与观察时间。转化按下单还是支付计算，也要先约定，再开发诊断功能。 |
| **搜索优化**<br>优化关键词、标题、搜索首屏素材 | 否 | 标题和素材优化有现成基础可借用。搜索词分析仍要补充数据与方法，才能判断哪些词、哪些首屏素材值得调整。 |
| **推荐流量机会**<br>识别高转化但推荐曝光不足SKU | 否 | 需要推荐渠道的商品曝光和转化明细。行业热度、全店销量都无法单独说明推荐曝光不足，相关数据能否提供要由京东确认。 |
| **潜力SKU**<br>识别值得放大的商品 | 否 | 评价的是商品增加流量后是否值得继续投入，以及库存能否承接。数据可以与商品经营模块共用，但应保留本项侧重流量放大的评价目标。 |
| **流量放大策略**<br>输出搜索、推荐、广告等组合增量方案 | 否 | 跨渠道方案需要新开发，结合商家预算、经营目标和各渠道表现提出建议。实际带来多少增量，要在执行后验证。 |

流量分析需要具体到商品、渠道和时间的报表，曝光、点击、成交及退款修正的口径应由双方统一。

## 五、活动经营能力

活动能否参加、怎样报名，要按京东的具体规则判断。我方需据此开发资格判断、推荐、收益测算和复盘功能。

原清单重点场景包括：官方直降、首购礼金、秒杀、特价、便宜包邮、百补、顺手买、买赠、换购、焕新补贴。 这些活动需要逐场景确认，不能按一套通用促销规则统一处理。

| 产品需求与原始目标 | 招标方已有流程 | 产品评估 |
|---|---|---|
| **活动资格识别**<br>判断商品可参加哪些活动 | 是 | 京东需提供活动门槛、适用商品范围及当前资格依据。招标方已有流程可供对接参考，但其中的规则和调用权限尚未提供。 |
| **最优活动推荐**<br>根据利润、库存、价格选择最适合活动 | 否 | 推荐方法要新开发。先明确商家看重销量、利润还是其他目标，再结合资格、库存和冲突条件比较活动。 |
| **活动收益测算**<br>测算活动预期GMV及利润 | 否 | 测算与预测需要专门开发。按假设计算可以给出收益情景；要预测实际成交，还需历史样本，并说明预测可能有多大偏差。 |
| **活动冲突判断**<br>判断价保、价格保护及其他活动冲突 | 是 | 判断须依据官方规则或平台校验结果，确认活动叠加、价保及补贴限制。事后价保记录不足以判断报名时会不会冲突。 |
| **一键提报**<br>支持直接报名或生成提报底表 | 是 | 可以按原文选择直接报名或生成底表。底表需明确模板和校验要求；直接报名还需报名、审核及结果查询能力，生成底表不代表报名成功，两种方式需分别验收。 |
| **活动复盘**<br>分析活动前后增量效果 | 否 | 需要活动对应的成交、费用和对比资料。前后变化可以统计；要进一步判断增长是否由活动带来，还要设置合适对照，考虑同期其他变化。 |

各类活动的资格、价格库存门槛、叠加规则和费用承担，要逐一核实。对暂不能直接报名的场景，还需确认底表是否满足交付要求。

## 六、广告经营能力

已有资料包含广告计划创建、预算调整和启停等接口，京喜适用范围及接入条件仍需确认。我方还要开发选品、调优和复盘逻辑，并与京东统一效果数据的计算口径。

| 产品需求与原始目标 | 招标方已有流程 | 产品评估 |
|---|---|---|
| **广告选品**<br>识别适合启动广告的SKU | 否 | 选品方法需要综合商品历史表现、毛利和库存。已有广告计划的数据只能提供部分依据，尚不足以判断所有商品是否适合开始投放。 |
| **投放方案**<br>输出计划、预算、ROI目标及出价建议 | 否 | 方案生成与校验需要开发。预算、出价和投产目标要同时符合商家成本、账户条件及所用广告产品的规则。 |
| **一键建计划**<br>支持自动创建广告计划 | 否 | 已有创建接口资料，可据此开展对接。京喜适用范围、必填参数和权限仍待确认，产品也要分别检查计划是否建成、是否开始投放。 |
| **智能调优**<br>根据实时数据调整预算、出价、ROI | 否 | 调优策略和执行控制需要专门开发。成交反馈可能延迟，调整过早容易误判；数据多久更新、各参数能否修改，都要先确认。 |
| **放量**<br>识别高ROI计划并扩大预算 | 否 | 增加预算后，投放效率可能变化。产品要设定增幅和观察条件，再判断是否继续扩量；无人值守执行须有明确授权。 |
| **止损**<br>对低效计划及时降预算/暂停 | 否 | 可按低效阈值开发降预算和暂停功能。判断时要考虑尚未回传的成交，执行后检查调整是否生效，避免误停。 |
| **创意生成**<br>自动生成广告图片及卖点 | 否 | 可复用商品素材和信息生成基础，按广告规格调整表达。本项只要求生成图片和卖点，可以由商家提供商品资料，不必先接入广告效果。 |
| **关键词优化**<br>增词、删词、强化高价值关键词 | 否 | 需要词级效果数据，以及对已有关键词增删的操作。当前资料虽有关键词字段，仍不足以确认这些操作完整可用，需与京东核实。 |
| **广告复盘**<br>分析GMV、ROI、消耗效率 | 否 | 效果分析需要开发。资料中已有曝光、点击及部分成交、费用字段，接入前还要统一成交归属、金额单位和统计时间。 |

广告对接应先确定可用广告产品和操作范围，再核对预算限制、成交费用口径。自动调整必须在商家授权内执行。

## 七、店铺及服务能力

订单、售后和客服已有部分公开数据可用于开发。这些业务产品还要按店铺规则设计功能；通用软件基础只能承担部分工程工作。

| 产品需求与原始目标 | 招标方已有流程 | 产品评估 |
|---|---|---|
| **店铺升星助手**<br>计算距离下一星级的差距并生成最短提升路径 | 是 | 京东提供星级规则、当前指标和升级阈值后，才能开发差距分析。“最短提升路径”也要先定义衡量标准。 |
| **客服诊断**<br>识别超时咨询、高频问题、排班空档 | 是 | 会话、聊天、等待时长和在线状态可用于分析。排班空档还要对照计划班表与实际工作记录，仅有当前在线状态不够。 |
| **AI客服回复**<br>自动生成并配置回复模板 | 是 | 回复内容与模板管理要开发。生成话术之后，还需能保存、审核和启用模板；消息发送接口无法替代这部分配置。 |
| **履约诊断**<br>分析揽收率、延迟发货、配送时效 | 是 | 已有订单时间和物流轨迹资料。计算时要按京喜考核规则明确订单范围、延迟时限，以及揽收、签收节点的识别方式。 |
| **售后诊断**<br>自动读取售后原因并给出解决方案 | 否 | 公开资料已明确提供一级、二级售后原因，可用来开发诊断功能。建议怎么处理，还要结合售后政策和商家情况；调用权限及京喜适用范围待确认。 |
| **售后沟通话术**<br>自动生成消费者沟通内容 | 否 | 可开发由商家提供售后场景的话术工具。内容应准确表达处理方案，不写无依据的赔付承诺；原文未要求自动发送。 |
| **店铺层级助手**<br>拆解距离下一经营层级的差距 | 是 | 取得经营层级规则和当前指标后，再开发差距拆解。经营层级与店铺星级各用什么规则，须分别确认。 |
| **店铺装修优化**<br>根据店铺流量及CVR优化页面结构 | 否 | 分析需要页面结构、访问路径和转化资料。交付是页面调整建议，还是直接修改并发布装修，也要事先约定。 |
| **会员运营**<br>会员招募、分层、权益及复购运营 | 否 | 会员资料、消费统计和部分权益已有接口基础。招募、权益配置、触达及效果跟踪仍待补齐，并要确认适用会员体系与用户授权要求。 |

这一模块需京东提供的内容包括星级与层级规则、客服模板配置方式、排班资料来源、履约和售后政策，以及会员招募与触达的可用操作。

## 八、经营自动化能力

多个任务同时出现时，系统要决定先做哪一个、哪些能自动执行、出错后如何处理，并检查执行效果。这套能力需单独建设，不能直接从现有生图或巡检产品中推定。

| 产品需求与原始目标 | 招标方已有流程 | 产品评估 |
|---|---|---|
| **AI任务编排**<br>多条规则同时触发时进行优先级判断及任务排序 | 未说明 | 规则优先级、任务冲突和状态管理需要单独建设，可由我方实现。现有软件基础及京麦任务记录功能尚不能证明已有完整编排能力。 |
| **AI自动执行**<br>获得授权后自动调用商品、价格、活动、广告工具 | 未说明 | 要逐项接通商品、价格、活动和广告操作，设置授权、额度限制及失败处理，并允许人工暂停。能自动执行到哪一步，取决于各项操作是否可用。 |
| **自动复检**<br>任务执行后自动监控对应指标是否改善 | 未说明 | 把每次动作与后续指标关联起来，先查修改是否生效，再看经营表现。不同任务需要不同观察时间和指标，应分别约定。 |
| **AI经营复盘**<br>自动生成经营日报/周报 | 未说明 | 各模块数据汇总后，再开发日报、周报。数据是否齐全、计算是否一致、更新是否及时，会直接影响报告的可信度。 |
| **策略A/B实验**<br>对不同经营Solution进行实验验证 | 未说明 | 双方要先选定可测试的经营方案，约定对照分组和评价方法。素材实验只能提供部分参考，其他经营策略的实验条件仍需设计。 |
| **策略学习**<br>基于历史Action→Result持续优化策略 | 未说明 | 要长期记录每次经营动作及其结果，再验证策略调整是否有效。这项能力尚未确认具备，需要专项建设；评价时也要区分策略作用与同期自然变化。 |
| **异常预警**<br>自动识别经营异常并触发任务 | 未说明 | 预警要有持续数据和异常判断，还要处理重复提醒、自动触发任务。修改商品或调整预算的权限，应与发现异常、创建任务分别管理。 |

自动化对接要明确谁负责执行、怎样取得业务结果，以及哪些实验需要平台参与。数据更新速度也必须满足约定的监控要求。

先约定多久需要看到变化，再选择定期查询或平台主动通知。能够满足时效的查询方式，也可以采用。

## 后续沟通事项

以下事项确认后，就能进一步确定各项功能的交付范围：

| 需要确认的事项 | 确认后能解决什么问题 |
|---|---|
| **商品内容规则与发布方式**：可修改哪些内容、需要哪些校验、如何确认生效 | 确定一键发品、属性补全、信息分优化及批量替换的完整交付范围。 |
| **经营数据范围**：具体商品、渠道、活动和页面能提供哪些指标，更新多快 | 确定潜力商品、流量诊断、经营复盘和执行后检查的可靠程度。 |
| **竞品、成本及费用来源**：同款与价格、商家成本、广告费用和补贴怎样取得与计算 | 明确比价、建议价格、毛利测算和投放底线的依据。 |
| **活动及广告操作**：哪些场景支持查询、报名、调整和停止 | 确定能直接执行的功能，以及需要商家确认或使用底表的场景。 |
| **店铺服务与会员规则**：星级、层级、客服、履约、售后和权益分别采用什么标准 | 避免产品计算与平台考核不一致，并明确可执行的服务动作。 |
| **授权、监控及实验责任**：哪些动作可以自动做、如何暂停、怎样判断有效 | 确定自动经营的安全边界和结果验收方式。 |
