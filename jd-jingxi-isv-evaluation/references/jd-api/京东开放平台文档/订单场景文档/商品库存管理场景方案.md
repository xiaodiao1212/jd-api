本文档重点介绍商家通过开放平台接口对接库存管理的流程及方案说明。库存管理是指商家为京东所有涉及交易的商品进行的销售库存的管理活动，主要包括以下几部分：设置库存模型/扣减方式、查询库房信息、获取库存模型/库存信息、设置库存。

## 一、基础概念

## 1.1 名词解释

| **名词** | **解释说明** |
| --- | --- |
| 京云仓 | 京云仓是京东为多平台商家（不仅限于京东平台）提供的仓储及配送服务，支持 **京东配送或第三方配送**。商家将商品存入京东仓库，订单由商家系统下传至ECLP系统进行履约  PS:京云仓不涉及库存管理接口及对接方案，一般使用物流的WMS系统记性管理 |
| 现货库存 | 指库存记录的某个SKU在仓内的数量总和，是当前上架的真实货物数量。 |
| 可用库存 | 可用库存为可下单货物数量，即现货库存减去预占库存。 |
| 订单预占库存 | 因用户下单所预占的货物数量，包括待付款及已付款未出库的订单预占；待付款预占库存会随用户取消订单而进行释放。 |
| 申请单锁定库存 | 锁定库存，就是一种锁定功能，比如有换新单 要预留库存 可以锁库存，总的锁定数量（即包含采销锁定数量+调用申请单锁定接口锁定的数量+直播锁定等） |
| 预订库存 | 商品尚未到货或暂时无现货，但用户可以提前下单预订，这类商品一般会在下单后的2-20天内发货，具体时间取决于商品的采购、生产或运输周期。预订库存用于协调供应链与用户需求，确保商品能够及时补货并满足订单。 |
| 厂直 | 厂商直送业务是京东自营的一种业务模式，业务特点为商品不入京东仓，由京东指定的厂家或供应商提供发货、配送及售后服务，商品物权属于京东，由京东开发票；它通过合理利用供应商资源，降低京东仓储物流成本，扩大自营销售； |
| 社会化 | 社会化库存是一种自营商品新的销售模式，即前台展示为自营商品，可由自营供应商直接履约订单，实现针对同一个sku，在同一个地址多个供应商+自营大仓同时供需，系统根据业务配置规则+库存智能决策模型最终考虑成本、时效、周转、区域、整单等综合因素后，决策使用那个供应商或自营大仓履约订单最合理的新销售模型，线上已支持大仓标准配送时效或门店快时效模型，如果使用供应商履约订单，在出库时刻进行以销定采，转移物权给京东，逆向售后可配置由供应商负责或京东负责； |
| 五星 | 五星是京东自营的一种特殊业务模式，线下模式是总部-分部-门店三级架构，各个分部独立经营，各个分部独立与当地区域供应商签订合同，普遍存在同一个商品被多个供应商操作的场景，一品多商是五星现有厂直业务的基础需求  商品为五星厂直商品：是由 「 sku+供应商+OU主体」 维度来维护SKU为厂直商品，厂直商品自定义。 OU主体，即采购主体  五星与自营模式再库存管理方面的差异  1. 库存维度： - 五星商品引入了OU（采购主体）的概念，库存管理在供应商维度下进一步下沉到OU维度，即库存管理维度为SKU + 供应商 + OU。 	- 普通自营商品仅在SKU + 供应商维度进行库存管理 3. 库存校验与履约 - 五星商品在结算页校验库存时，可以预占多个供应商的库存，但同一SKU不能同时走自营和厂直模式。 	- 普通自营商品库存校验和履约逻辑相对简单，不涉及OU维度的复杂判断 |

## 二、业务规则

## 2.1 库存模型

库存模型分全国库存和分区库存两种模式，主要用于计算可用库存计算及定位逻辑

- **pop全国，** 即一仓覆盖全国的方式进行销售，不需要商家手动维护仓的覆盖范围。设置库存入口：如上图所示，商品sku详情。
- **pop分区，** 即商家开通1个甚至多个仓，并且分配对应的覆盖进行销售。分区仓初始化设置入口： [京麦端-分区库存管理](https://storehouse.shop.jd.com/partitionWarehouse/list)，设置完成后，在 [分区库存管理](https://ware.shop.jd.com/rest/shop/stock/manage/index) 进行库存维护。

特别关注：库存模式由全国模式切换为分区模式后无法切回，请谨慎操作

## 2.2 库存扣减方式

> 库存计算方式有两种方案： **订单发货扣减现货库存方案** 或 **订单支付扣减现货库存方案**，商家根据自己系统的逻辑选择其中一种计算方案，选择计算方案后提供给JD运营进行配置（目前仅大时尚业务支持配置，其他业务需要额外提需 单独处理），后续对接接口后会按照选择的方案进行计算。
> 
> 扣减模式选择：订单发货/支付扣减均支持预占用的逻辑，选择何种方式，主要取决于对接的上游OMS系统的库存计算逻辑。
> 
> **！** 特别关注：在不做业务配置的情况下，默认的库存扣减模式为 **发货扣减。**

**发货/支付扣减模式核心差异点说明**

1. 预占逻辑差异
	- 发货扣减：订单无论是否支付都会走预占的逻辑
	- 支付扣减：仅订单提交但未支付会走预占的逻辑
2. 现货扣减/预占释放逻辑差异
	- 发货扣减：订单出库（发货）预占会被释放，同时扣减现货库存
	- 支付扣减：订单支付时预占会被释放，同时扣减现货库存

## 2.3 库存计算逻辑

**库存的计算公式为**：

- 可用库存=【现货库存stockNum】-【预占库存orderBookingNum（未支付订单预占+已支付订单预占）】-申请单锁定库存appBookingNum

**库存变化节点：**

订单发货扣减现货库存模式/订单支付扣减现货库存模式，库存变化节点存在逻辑差异，详情见下方表格，差异点已高亮标注

| **模式** | **库存变化节点说明** |
| --- | --- |
| 订单发货扣减现货库存 | - 可用库存减 - 自动减：1.订单提交时产生库存预占orderBookingNum增加；2.申请单锁定库存appBookingNum产生，为了给换新预留库存用 	- 设置减：商家自行设置现货库存stockNum减少 - 可用库存加 - 自动加：订单提交后、未出库前取消，则预占库存orderBookingNum减少，可用库存增加； 	- 设置加：商家自行设置现货库存增加stockNum； - 现货库存减 - 订单发货（出库）时 	- 商家自行设置现货库存stockNum减少 - 现货库存加 - 商家自行设置现货库存增加stockNum |
| 订单支付扣减现货库存 | - 可用库存减： - 自动减：1.订单提交但未支付前产生库存预占orderBookingNum增加；2.申请单锁定库存appBookingNum产生，为了给换新预留库存用 	- 设置减：商家自行设置现货库存stockNum减少 - 可用库存加： - 自动加：订单未支付取消，则预占库存orderBookingNum减少，可用库存增加； 	- 设置加：商家自行设置现货库存增加stockNum； - 现货库存减 - 订单完成支付时 	- 商家自行设置现货库存stockNum减少 - 现货库存加 - 商家自行设置现货库存增加stockNum |

特别关注：为避免超卖（可用库存小于0），需关注现货库存stockNum、预占库存orderBookingNum的变化及时增补库存数量

## 3.2 操作步骤

### 3.2.1 设置库存模型/扣减方式

1.设置库存模型/扣减方式

**库存模型** （全国/分区），可通过商品编辑接口或京麦端进行修改，特别关注：切换到分区库存保存后，无法回退到全国模型，请谨慎操作

**库存扣减方式（** 订单发货扣减/订单支付扣减）以商家维度进行设置，目前暂未开通配置页面，选择计算方案后提供给JD运营进行配置（目前仅大时尚业务支持配置，其他业务需要额外提需 单独处理）

- 库存模型设置
	- 发品编辑接口：POST sp-product/v0/product-applies
- 库存模型可以在发品时或者编辑时进行设置、修改，对应字段为nationallySetWare
	- 库存模型可以商品维度进行设置，入口为发品页或者编辑商品页

1.查询库存列表

本步骤使用的接口： [jingdong.store.findPartitionWhByIdAndStatus](https://open.jd.com/v2/#/doc/api?apiCateId=127&apiId=750&apiName=jingdong.store.findPartitionWhByIdAndStatus&gwType=0)

### 3.2.3 获取库存模型/库存信息

1.查询SKU库存模型/库存量

本步骤使用的接口：

[GET sp-product/v0/sku-stocks](https://open.jd.com/v2/#/doc/api?apiCateId=200375&apiId=100667&apiName=listSkuStocks&gwType=1) 目前仅支持POP模式，其余模式后续会融合至该接口，暂时可使用下方列举的旧版接口

- 可以通过以上接口查询SKU当前的库存数量（现货库存、订单预占库存等明细项）
- 特别关注，五星模式下需要传入经营主体ID（ouId），可从京麦分区库存管理页面获取 [https://ware.shop.jd.com/rest/shop/stock/manage/inde](https://ware.shop.jd.com/rest/shop/stock/manage/index)

### 3.2.4 设置库存

1.设置SKU库存

[PUT sp-product/v0/sku-stocks/batch](https://open.jd.com/v2/#/doc/api?apiCateId=200375&apiId=100671&apiName=batchPutSkuStock&gwType=1) 目前仅支持POP模式，其余模式后续会融合至该接口，暂时可使用下方列举的旧版接口

厂直及社会化库存设置： [jingdong.stock.open.api.updateVenderStockNum](http://jhub.jd.com/index.action#/control/serviceInfo/20145/com.jd.stock.bk.export.BkStockNumUpdateExport/api-info?id=20145)

五星供应商sku库存设置： [jingdong.ware.stock.sku.fivestar.set](https://open.jd.com/v2/#/doc/api?apiCateId=48&apiId=100024&apiName=jingdong.ware.stock.sku.fivestar.set)

- 支持以全国/分区库存模型进行更新
- 支持增量/全量更新库存数量（更新的为现货库存），推荐增量更新模式（目前厂直、五星模式暂不支持增量更新）
	- 适用场景：每次设置为覆盖逻辑，适用于 **初始化或基准校准** 的场景，直接覆盖旧值，避免增量累积错误
	- 特别关注：库存数量减少需谨慎，如若因设置库存过少导致超卖易产生客诉，例如：当前现货库存10、订单预占库存8，此时设置库存时将现货库存改为5，将会产生3笔预占订单无货出库。
	- 适用场景：每次设置是在当前剩余库存基础上进行增减，适用于 **库存频繁变动场景**，提升响应速度
	- 此方式可大大降低因库存修改导致的超卖问题， **推荐使用增量更新**。

## 五、常见问题

## 5.1 业务类常见问题

1.分区仓为何会有一个storeid为0的数据？

storeid为0的是默认的商家全国仓，每个商家都有

2.ICF库存是否可以支持设置/查询？

ICF商家目前可以设置分区&全国库存；查询仅可查询全国仓库存，不支持查询分区仓库存

3.如何查询库存流水？

可以在京麦工作台-店铺-账号操作日志页面下查询，后续会开通库存流水消息
