POP是京东的“平台开放计划”，区别于京东自营，属于第三方卖家借用京东平台来销售商品。目前京东商家开放平台POP业务下，支持SOP、门店发货、门店自提、到店业务四大核心子模式的开放能力的场景对接，其中SOP代表京东零售主站B2C线上电商，门店发货、门店自提、到店业务代表以POP商家线下门店为核心的本地生活的即时零售业态。

## 一、POP模式介绍

## 1.1 POP模式与关键子模式

Platform Open Plan，是京东的“平台开放计划”，京东POP平台区别于京东自营，属于第三方卖家借用京东平台来销售商品。POP业务围绕商品定价权、物权、仓配、开票结算、售后、场等衍生多种业务形态，其中根据"场"的不同，可分为：

- **POP-B2C模式：** 京东零售主站线上电商，主要包括SOP模式；
- **POP-O2O模式：** 包括门店自提、门店发货、到店业务。

## 1.2 POP关键子模式说明

京东平台POP-B2C主要以SOP模式为主，本文档仅对SOP模式做解释说明。

## 二、POP-SOP模式介绍与对接方案

SOP（Sale on POP）模式是商家仅使用京东平台交易产生订单，由商家以其自身名义进行商品信息上传、展示、咨询答复、商品销售、发票开具、物流配送服务及售后服务提供等，商家也可选择部分 SKU入仓到京东仓库，京东负责存储、打包、发货、物流。

| **SOP-入京仓** | **SOP-不入京仓** |
| --- | --- |
| - 模式概况：商家采货入京东仓（商务仓或云仓），用户下单后订单进入京东仓，用京东物流配送到用户手中 - 合同：POP入驻协议+物流仓储配送/云仓系统协议 - 仓配：商家有足够的备货实力，商家采货入京东仓，用户下单后订单进入京东仓，用京东物流配送到用户手中 - 客服：由商家负责店铺维护、售前售后服务 - 发票：由商家给消费者开发票 - 货权&定价权：归属商家 - 前台展示标识：POP+京东物流 - 时效：自营时效 - 仓经营方：京东 - 仓配费用承担方：商家 - 正、逆向物权转移节点：京东与商家之间不存在转移 - 拒收返回的仓：商家仓 - 售后物流返回仓：商家仓 - 换货换新：支持换货、不支持换新（具体依据商家售后政策而定） | - 模式概况：商家采货入商家仓，用户下单后订单进入商家仓，用京东物流/三方物流配送到用户手中 - 合同：POP入驻协议 - 仓配：商家有自己完备的货、仓、配资源，商家采货入商家仓，用户下单后订单进入商家仓，用京东物流/三方物流配送到用户手中 - 客服：由商家负责店铺维护、售前售后服务 - 发票：由商家给消费者开发票 - 货权&定价权：归属商家 - 前台展示标识：POP - 时效：POP时效 - 仓经营方：商家/第三方 - 仓配费用承担方：商家 - 正、逆向物权转移节点：京东与商家之间不存在转移 - 拒收返回的仓：商家仓 - 售后物流返回仓：商家仓 - 换货换新：支持换货、支持换新（具体依据商家售后政策而定） |

## 三、POP拓展模式介绍与对接方案

## 3.1 门店发货模式

**模式介绍**

POP门店发货业务，是在POP-B2C业务基础上，将POP商家线下门店（加盟/直营门店）及商品，上传到京东平台，形成一商多店的管理模式，以中心化的店铺视角，统一建品、定价、促销、销售。用户在主站购买商家商品，如该商品附近有可履约的门店，默认会展示同城配送（如无可履约的门店，会做大仓兜底），由门店进行商品履约。

**特性要求说明**

相较于普通SOP商家，合作门店发货的POP商家，需先在京麦端开启门店发货的相关服务，在API场景对接方案上会在SOP的对接基础上，新增部分门店发货商家特性化能力，主要包括：

1. **门店管理：** 商家需完成门店创建、配置履约规则、绘制围栏、以及按门店维度配置开通达达服等；
2. **门店商品：** 支持以商品或sku纬度对商品进行打标（打标值sku_mark 16=1），从而实现商品在前台漏出门店发货业务标识别；
3. **门店库存：** 需按照skuid+门店id纬度进行售卖商品的库存信息同步；
4. **门店订单：** 开通门店发货的POP商家支持门店纬度的订单出库履约，通过“orderSign ”字段判断订单是否为门店发货订单；
5. **门店售后：** 商家可通过线下联系运营的方式申请门店售后，开通后消费者在申请售后是可选择期望取件方式为：送货至门店、快递至门店、门店上门取件；
6. **门店结算：** 门店发货账单下沉至门店纬度，商家可以根据需要进行API对接。

**特性要求说明**

相较于普通SOP商家，合作到店业务的POP商家，需先在京麦端开启到店业务的相关服务（服务类型、发码方式、触发结算方式、费用结算方式、过期退随时退等等），在API场景对接方案上会在SOP的对接基础上，新增部分到店业务商家特性化能力，主要包括：

1. **门店管理：** 商家需完成门店创建、状态维护和修改，实现商家线下门店实际经营情况和线上漏出状态一致；
2. **门店组：** 需创建门店组，用于门店分堆管理，以及进行更新、删除门店与门店组的关联；
3. **到店商品：** 发布loc商品，除了维护商品基础信息外，需要设置SPU维度特殊属性features，主要包括：到店服务（isLOC=1）、服务有效期-开始时间（effectiveStartDate）、服务有效期-结束时间（effectiveEndDate）、购买成功后有效天数（locRelativeTime）、服务类型（locfwlx）、门店组（locGroupid）；
4. **订单发码：** 包括京东发码，商家发码，其中：
- 商家选择京东发码方式时候，则无需进行发码流程对接，只需要对接核销流程；
	- 商家选择商家发码方式时，则有同步发码和异步发码两种方案，京东通过SPI方式同商家券码系统进行对接；
6. **核销码：** 消费者到店消费后，支持商家通过接口进行券码的核销，以及逆向场景下的核销冲正；
7. **到店售后：** 京东平台的到店业务（LOC）订单默认支持随时退、过期退，不需要商家审核即完成退款给用户，支持商家通过售后接口获取以上服务单信息。

## 四、POP开放场景对接方案全景

开发者在京东商家开放平台控制台可以选择需要对接的场景能力，目前京东商家开放平台POP业务下，共分SOP、门自门发、门店自提、到店业务四大核心子模式，其中SOP子模式下开放有8大一级业务场景，包括：商品、订单、售后、财务、营销会员、直播、客服、特色场景等。
